# 系統架構

參考對象：臺大學習規劃辦公室（https://aaoffice.ntu.edu.tw/Service）。他們用「學習規劃師會談 → 媒合同儕／業師 → 後續追蹤」的流程，幫學生從課業連到未來。這個 DEMO 把規劃師的工作拆成 AI 做得好的部分，**決定仍由學生和老師做**。

## 整體

## 會談流程（對照臺大學習規劃辦公室）

```
首頁 ──→ 會談前 ─────────────────→ 會談 ───────→ 整理 ─────────────→ 自評表 ──────→ 會談紀錄
        ① 選議題（9 項，依階段）     對話＋工具     AI 整理「今天聊了」    方向清楚度（再問一次）  可匯出 PDF／圖片
        ② 方向清楚度 1–5            若有上次行動，   「你的發現」         最有幫助的是？          給課諮師、導師
        ③ 成績單／興趣測驗           先關心進度      學生自己寫下一步      對下一步的信心
           拍照（AI 讀）或手動        學生按「結束」   （AI 不代訂）        AI 有沒有說錯
           → 學生確認才進側寫                                         一句話反思
                                                                     （填完才能開下一次）
```

| 臺大做法 | DEMO 對應 | 程式 |
|---|---|---|
| 預約時寫想談的議題 | 會談前選議題＋補充 | `data/stages/*.json` 的 `topics` |
| 可上傳成績單、心理測驗結果 | 拍照由 Claude 讀取（結構化輸出），或手動輸入；學生確認才寫入 | `planner/extract.py`、`session.suggest_strengths` |
| 一小時會談、規劃師引導 | Agent 對話 | `planner/agent.py` |
| 學生自己決定下一步 | 結束後學生自己寫 1–3 個行動 | `web/app.js` renderWrapup |
| 會後 1 週內填自評表才能再預約 | 自評表填完才能開下一次 | `web/app.js` renderSurvey |
| 行動後反思、再會談 | 下次開場先關心上次的行動，`update_action` 記錄進度 | `session.kickoff_message` |
| （串連真人） | 會談紀錄可匯出給老師，含「可以帶去問老師的問題」 | `planner/summary.py` |

**評估指標**：每次會談前後各問一次「方向清楚度」，差值就是這次會談的效果。

## 個人化迴圈

```
學生說話 → Agent 判斷有新資訊 → 寫入側寫（附原話）→ 學生在右側看到、可以要求更正
    ↑                                                        │
    └──── 下一輪：側寫放進 prompt、差距分析以側寫計算 ←─────────┘
```

## 設計決定

| 決定 | 理由 |
|---|---|
| 側寫是結構化 JSON，不是聊天紀錄 | 可以顯示、可以計算、可以讓學生更正；聊天紀錄換一個分頁就沒了，側寫會留著 |
| 每筆側寫變更都要附學生原話 | 可解釋：AI 為什麼這樣認為一目了然；也防止 AI 記下自己猜的事 |
| 側寫存瀏覽器 | 使用者是未成年人，伺服器不存個資 |
| 差距分析、契合度由程式算 | 數字可重現、可測試（tests/test_core.py）；LLM 只負責對話與解釋 |
| 危機偵測放在 LLM 之前 | 對未成年人，明顯的危機訊息不能依賴模型判斷；寧可誤判也要轉介 |
| 國中／高中差異全放在階段包 | 還沒決定做哪一個，核心程式不用改 |
| 方向資料用關鍵字搜尋，不用向量 | DEMO 只有幾筆資料，全部比對就好；資料量變大再換成 RAG |
| 模擬學生評估（eval/simulate.py） | 開放式建議沒有標準答案，先用 LLM 扮演不同學生跑完整對話，再自動檢查側寫有沒有落在合理位置 |

## 還沒做（之後的方向）

- 真實資料：高中改用 ColleGo! 學群資料、各校系建議修課；國中改用適性入學資料
- 成績匯入與趨勢、學期追蹤提醒
- 學習歷程檔案的成果建議
- 給課諮師看的「會談前摘要」（學生同意後匯出側寫）
- 真人評估：請課諮師或輔導老師看模擬對話打分
